# src/asn1 — TSE's fork of the III ASN.1 runtime

The app encodes and decodes its records with the **III ASN.1 Tool** runtime (namespace `ASN1`), in a fork TSE made of
it, and with the classes asnparser generated from TSE's ASN.1 specifications (namespaces `Modulo*`). Upstream is
fetched into `third_party/III-ASN.1` by `tools/setup/bootstrap.sh` (last commit 66e5d48; gitignored, like the other
checkouts); the lineage and the measurements behind everything below are
in [docs/reference/facts/asn1.md](../../docs/reference/facts/asn1.md) (§A0–§A4).

The upstream files here are a modified copy of the III ASN.1 runtime at that commit, under the Mozilla Public License
1.0: each keeps its upstream licence header, and the changes made to them are in this repository's history.
`AssocVector.h` comes from the Loki library and keeps the permission notice in its header.

## How it is built

`src/mk/asn1.mk` compiles every `*.cxx` here at `-Os -fexceptions -fignore-exceptions -std=c++17 -DNDEBUG`: a `throw`
compiles to a direct `__cxa_throw`, as in the target, where no ASN.1 function calls an `invoke_*` import, and libc++'s
inline functions carry the `ne` ABI tag the rest of the program shares (facts §A2). Nothing in the skeleton calls the
runtime directly yet, so a roots TU generated by `tools/round/gen_try_roots.py` keeps its objects in the link. The
modules are compiled with the same flags plus `-Isrc/asn1/modules`; the converters' fragment
(`src/units/04-ecourna-app-dados-asn.mk`) puts them in the link. The generated roots take the address of every external
function, so one the target only calls, and inlines where it has one caller, must be left out of them:
`ASN1_ROOTS_EXCLUDE` in `src/mk/asn1.mk` lists such functions, and a unit's fragment can add to it with `+=`.

The headers are C++20-clean, because the ecourna TUs (`-std=c++20`) include `asn1.h` and the module headers:
`asn_ptr<T>` is `std::unique_ptr<T>` (the target's `~CHOICE`, 997/8997, stores 0 before it deletes, which is
`unique_ptr::reset()`), lambdas replace `bind2nd`/`not1`, and `AssocVectorCompare` takes the key type. The runtime's
own objects are C++17: `BERDecoderPartial::do_visit(OBJECT_IDENTIFIER&)` (8841) builds a `shared_ptr<char[]>`, and at
`-std=c++20` functions 3477 and 8848 stop matching.

To score the runtime alone against the target's ASN.1 slice: `tools/libs/asn1/build.sh <name> -Os -fexceptions
-fignore-exceptions -DNDEBUG`, then `tools/libs/census_subset.ts` on the result (`tools/libs/asn1/flags.txt` holds the per-file extras).

The runtime's objects go through `tools/round/gen_try_roots.py`, which takes the address of every external function, so a
function the target only calls has to leave those roots, or binaryen keeps its result and never inlines it. `src/mk/asn1.mk`
holds `ASN1_ROOTS_EXCLUDE`, and a unit's fragment adds to it with `+=`.

## The generated modules

`modules/` holds one header and one source per `Modulo*` module, 32 of each, in asnparser's output style. The target
keeps the whole schema of these types in its data: every generated class has a static `theInfo` record, and TSE's
asnparser appends the type's name to it (facts §A3). The 297 records give the field names, order, tags and
optionality, the enumerators and the constraints exactly. Class names come from RTTI, from the names the app's
`std::source_location` records spell, or are made up from the field name; the 13 made-up ones say `SYNTHESIZED` in
their header comment. A generated class has no code of its own (all `SEQUENCE` classes share seven vtable functions),
so the modules place data, not functions.

`tools/extract/asn1/run.sh` regenerates them from the target into `build/out/asn1-schema/modules/` (about 15 s;
it needs `build/dump/vota.objdump.txt`). Its output differs from the committed modules in 17 files, which carry
hand edits made after generation: setters that take
`x::const_reference` for every field, as asnparser writes them; generated classes that the target does not have
(`Cabecalho`, nested `value_type`s) replaced by a `typedef` of the type it uses; an inline enumeration turned into
the named type the target's RTTI shows (`ModuloTiposEcoUrna::SituacaoArquivo`) and a string type added
(`ModuloTiposEleitorais::DataHoraJE`); typedefs for the names the app's source spells (`EstiloTitulo`,
`GeneroLabel`, …); a made-up class name replaced by the one RTTI shows (`ModuloEstadoGeralUrna::TipoUrnaOperacao`);
and the `#include` C++20 needs. So diff a regeneration against this
directory before copying anything over.
